给这个傅里叶教学工具补上它现在最缺的一块：让学生看清一段信号的频率成分是怎么随时间变化的。眼下这套工具只会把一整段离散信号当成一次性的东西来分析——选好点数、拨好采样率、加个窗，后端算一次离散傅里叶变换，前端把幅度、相位、功率三张谱线画出来，就完了。可现实里的声音、音乐、语音、扫频信号，频率是一直在动的，一段啁啾从低走到高、一段旋律里音符此起彼伏，用一次全局变换看，只会得到一堆糊在一起的谱峰，什么时候出现的、持续多久，全丢了。我们要加的是短时分析：把信号切成一串互相重叠的小段，每段各自加窗、各自做一次变换，把结果沿时间轴排成一张二维的时频图，让学生直观看到"哪个频率在哪个时刻、有多强"。

前端要新开一块时频分析区，和现有那几块并列，别挤进已经画着三张谱线的那块，也别塞进信号构造或采样定理那些地方——它是独立的一张二维热力图，不是往旧图上再叠一条线。学生在这里能拖三个东西：每一小段的长度、相邻两段之间往前挪多少（也就是重叠多少）、以及用哪种窗。这三个量一动，整张热力图立刻重画。横轴是时间、纵轴是频率、颜色深浅代表该时刻该频率的能量强弱，学生把鼠标移到图上任意一点，要能读出对应的时刻、频率和幅度值。段长和挪动步长都要有约束：段长得落在允许的档位里、步长必须为正且不超过段长（否则中间会漏掉采样点，画面就骗人了），挪动步长比段长小意味着相邻段有重叠，这正是时频图平滑的关键，要让学生能感受到重叠越多画面越顺、但计算量也越大的权衡。为了让这块有明确可看的教学效果，请再让学生能快速构造一个频率随时间线性扫上去的测试信号，这样时频图上就该出现一条清晰的斜线，斜率对应扫频速度——这是检验整块功能对不对的最直接的眼睛。

难点不在多画一张图，而在时间和频率这对分辨率是互相拽着的，改一个另一个就变。段取得越长，频率分得越细，但同一时刻的多个事件会被抹平、时间上说不清；段取得越短，时间上越利落，频率却糊成一团。这层此消彼长要让学生亲手拨滑块体会到：把段拉长，热力图纵向变细腻、横向变粗；把段缩短，反过来。页面要把当前设置换算出来的两个分辨率数字明白写出来——每一列在时间上代表多宽的一段、每一行在频率上对应多少赫兹——让权衡是可量化的、不是靠感觉。

后端是这块的算术根基，不能只是前端画图的取数口，它得自己站得住、能被独立检验。它要能接一段实数采样序列连同分段设置，把信号按设定切成一串重叠帧、逐帧加窗、逐帧变换，返回一个时间乘频率的二维强度矩阵，外加两根坐标轴：每一帧对应的时间中心、每一行对应的真实频率（按采样率换算）。这里有几条必须真实成立、并且要由后端自动化测试逐条守住的关系，不能只靠热力图看着像：其一，一段频率恒定的纯正弦切成多帧、逐帧分析，每一帧的能量都应集中在同一条频率行上，也就是热力图上是一条水平亮线，不能东飘西荡；其二，一段频率线性扫上去的信号，其能量峰值所在的频率行应当随帧序号单调抬升，也就是那条斜线的走向要正确、可被程序判定而不是肉眼估；其三，也是最难的一条——在满足恰当重叠与加窗的前提下，把切分出来的这串帧再拼回去、逆着变换回时域，必须能在数值误差内重建出原始信号（重叠部分要按加权正确叠加抵消掉窗的影响），这条"分了还能无损拼回来"的往返恒等式要有测试守住。为此后端还要对外提供逆向的一步：给定这串帧的频域表示，把它们重建成一条时域序列。

要挡回并说清原因的非法输入至少包括：段长不在允许档位；挪动步长不为正、或大于段长；信号短到连一整段都凑不满；重建时给的帧结构对不上。合法的退化情形照常给结果，比如信号正好只够切一帧，那张热力图就只有一列，不该报错。

实现上顺着现在的架构走：前端仍用 TypeScript 加 Vite、用 Canvas 画这张热力图、不引第三方图表库；后端仍用 Python 3.12 配 FastAPI，新增的分帧与时频计算要单独成模块，别塞进已有的单帧变换里，但底层的变换内核该复用就复用，不要另造一套。交付仍用 Docker Compose 把前后端一起编排起来，浏览器打开就能拖参数看时频图、后端接口对外可用，并随附覆盖单频水平线、扫频斜线走向、以及分帧往返重建这三条关系和上述非法输入的自动化测试。
